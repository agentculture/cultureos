# VENTUNO Q factory baseline

The "before" state of the Arduino VENTUNO Q (hostname `cultureos`) as shipped
with factory Ubuntu 24.04, captured read-only over `ssh arduino`. The NVMe
install task diffs against this document: the eMMC GPT partition table and the
UEFI `Ubuntu` entry must remain byte/entry-identical to the sections below.

Rules of capture: non-root commands only, nothing written to the board, no
secrets (no Wi-Fi PSKs, no tailnet keys, no MAC addresses, no SSID, no global
IPv6 addresses). Every section shows the exact command, then its output. The
whole document body is regenerated by `os/scripts/capture-baseline.sh`.

Captured: 2026-11-01. Board: Qualcomm (QRB) aarch64, eMMC `mmcblk0` (59.3G).

## Summary

- OS: Ubuntu 24.04.4 LTS (Noble), kernel `6.8.0-1078-qcom`, aarch64.
- Partitioning: 71-entry GPT on `mmcblk0`. Qualcomm firmware partitions are
  A/B pairs (`xbl_a`/`xbl_b`, `uefi_a`/`uefi_b`, `tz_a`/`tz_b`, `hyp_a`/`hyp_b`,
  `dtb_a`/`dtb_b`, and so on). The OS partitions are single-slot: `efi`
  (p69, vfat, 512M, `/boot/efi`), `persist` (p70, ext4, 30M, `/var/persist`),
  `system` (p71, ext4, 55.9G, `/`).
- UEFI: `BootOrder` = `0000`, `BootCurrent` = `0000`; `Boot0000` is the
  `Ubuntu` entry, `HD(69,GPT,...)/\EFI\ubuntu\shimaa64.efi`. Other Boot####
  variables are not exposed (only `Boot0000` is present in efivars).
- Watchdog: `watchdog0` is `qcom_wdt` (driver `17c10000.watchdog`), state
  `inactive`, timeout 30 s, systemd `RuntimeWatchdogUSec=0` (no userspace petting).
- Network: `wlp3s0` up (Wi-Fi, DHCP, default route), `end0` down (no carrier),
  `tailscale0` up (tailscaled running), plus `docker0` (down).

## Decoded UEFI entries

Decoded from the raw bytes shown in the sections below (4-byte efivar
attributes, then the variable payload):

| Variable | Decoded value |
|----------|---------------|
| `BootOrder` | `0000` (attrs `07000000` = NV+BS+RT, then one uint16 entry `00 00`) |
| `BootCurrent` | `0000` (attrs `06000000` = BS+RT, then `00 00`) |
| `Boot0000` | attrs `07000000`; load-option attributes `0x00000001` (ACTIVE); FilePathListLength `0x64`; description `Ubuntu`; path `HD(69,GPT,278e862b-5d8a-becf-1718-9b9731c06c8c,0x5c0800,0x100000)` then `\EFI\ubuntu\shimaa64.efi` |
